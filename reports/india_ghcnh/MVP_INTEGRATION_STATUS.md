# Rapid MVP integration status (measured 2026-09-30)

Factual status of the rapid-MVP integration on top of the existing SkyGuard
backend. No metric below is estimated: every number is read back from a run in
this repository. Paths are relative to `Backend/`.

## 1. Serving path that now works end to end

```
real GHCNh historical observation
        -> data quality (frozen DQ taxonomy)
        -> station-specific calibrated statistical detector
        -> unified detection result
        -> replay alert persistence
        -> WebSocket event (OBSERVATION / ANOMALY_DETECTED / REPLAY_COMPLETE)
        -> station / alert / network API
```

Verified live against the repository launcher (`python -m src.api.run`):
a `MUM-03` replay over `ws://127.0.0.1:8010/api/v1/live` produced 30
observations, 11 anomalies, `alerts_recorded=11`, chronological timestamps and
the required event fields on every message.

## 3. Unified detection result

`StationStatisticalDetector.score_frame()` returns one schema per row:
`station_id, timestamp, temperature, relative_humidity, pressure, anomaly,
severity, confidence, detector, primary_reason, contributing_factors,
data_quality, spatial_context` (plus `anomaly_score`, `confidence_basis`,
`pattern_estimate`). Values are human-readable strings; no Python enum
representation is exposed. `severity ∈ {NORMAL, LOW, MEDIUM, HIGH, CRITICAL}`
and `NORMAL` is only ever used when `anomaly = false`.

Confidence is derived from the detector's own statistic, not invented:
`z / (z + 3.0)` over the same max|z| that crosses the frozen z=3.0 rule, with
`confidence_basis` recording the formula and a note stating it is an
evidence-strength margin, not a calibrated probability. Normal observations and
IQR-only flags report `confidence = null` rather than a made-up number.

## 4. Controlled demo (existing benchmark injection infrastructure)

`python -m src.detection.demo` copies a real 30-day GHCNh window, applies four
faults with `src.benchmark.injectors` at parameter values taken from
`src.benchmark.config`, labels every injected row `CONTROLLED_DEMO` /
`BENCHMARK`, and scores the copy with the same detector replay uses. Injected
rows exist only in memory; the processed dataset on disk is untouched (verified
by test). Metrics per city (`<city>_controlled_demo.json`):

| Mumbai | 45 | 22 | 685 | 23 | 0.0311 | 0.4889 | 0.0585 | 0.491 |
| Bengaluru | 45 | 23 | 663 | 22 | 0.0335 | 0.5111 | 0.0629 | 0.475 |
| Hyderabad | 45 | 20 | 685 | 25 | 0.0284 | 0.4444 | 0.0533 | 0.491 |
| Chennai | 45 | 27 | 672 | 18 | 0.0386 | 0.6000 | 0.0726 | 0.482 |

Per-fault recall (injected, detected):

| city | SPIKE | FROZEN | DRIFT | CROSS_VARIABLE |
| --- | --- | --- | --- | --- |
| Mumbai | 1 / 1 (1.00) | 5 / 10 (0.50) | 11 / 24 (0.46) | 5 / 10 (0.50) |
| Bengaluru | 1 / 1 (1.00) | 2 / 10 (0.20) | 14 / 24 (0.58) | 6 / 10 (0.60) |
| Hyderabad | 1 / 1 (1.00) | 3 / 10 (0.30) | 12 / 24 (0.50) | 4 / 10 (0.40) |
| Chennai | 1 / 1 (1.00) | 5 / 10 (0.50) | 13 / 24 (0.54) | 8 / 10 (0.80) |

These results are poor and are reported as measured. Two mechanisms explain
them, neither of which was tuned away:

1. **Background flag rate ~48–49 %.** At 30-minute GHCNh cadence the frozen
   2-hour causal IQR window holds 6 rows (`horizons_for_cadence` minimum). On
   provider-quantised values the window IQR is frequently zero, so Tukey bounds
   collapse and any 1-unit change flags. The rule is the frozen z=3.0 / IQR=1.5
   rule and was left unchanged; this is the dominant remaining blocker.
2. **Fault-window recall ≈ 0.5 for FROZEN/DRIFT is a boundary effect.** A frozen
   sensor or a slow drift only departs from its own causal context after the
   environment moves, so the first half of each injected window is not yet
   statistically distinguishable. No injected row was withheld by the data
   quality layer (0 of 45 in every city).

Benign background rows are not proven normal by the benchmark methodology
(`ground_truth_anomaly = 0` means "not injected"), so `FP` here is
"flagged non-injected row"; the same number is reported as
`background_flag_rate`, and the untouched pre-injection window is reported
separately as `quiet_window.flag_rate` (Mumbai 0.478).

## 5. WebSocket contract

Every server message carries `type` (existing frontend contract, unchanged) and
`event_type` (replay contract): `CONNECTION`, `REPLAY_STATE`, `OBSERVATION`,
`ANOMALY_DETECTED`, `REPLAY_COMPLETE`, `ERROR`. OBSERVATION and
ANOMALY_DETECTED messages expose the required flat fields `event_type,
station_id, timestamp, observation, detection, severity, confidence, reason`,
plus `data_quality`, `contributing_factors`, `spatial_context`. Replay reports
`source_mode = HISTORICAL_REPLAY` and `split = HISTORICAL`; it is never labelled
live. Serialization of every event is asserted in tests.

## 6. Alert persistence

Anomalies are persisted through the existing SQLite persistence layer
(`src.live.store.LiveStore`) into a dedicated file
`data/replay/replay_alerts.db`, so replay records never mix with live
operational episodes or with the frozen operational alert feed served at
`/api/v1/alerts`. No schema change. Records are deterministic per
(station, timestamp, detector) and idempotent, carry
`status = RECORDED`, `interpretation = HISTORICAL_REPLAY_ANOMALY`, and expose
`station_id, timestamp, severity, confidence, reason, detector, status`. Normal
observations never create a record (enforced in `record()` and asserted in
tests). The triggering observation is stored with `source = HISTORICAL_REPLAY`
and `pressure_basis = altimeter_qnh_hpa`.

## 9. Remaining blockers

1. Background flag rate ~48–49 % on real Indian stations (zero-width IQR over a
   6-row window at 30-minute cadence). Needs a deliberate, reviewable decision
   on the IQR window/quantisation policy for sub-hourly provider data — this was
   out of scope for the rapid MVP and would change the frozen rule.
2. No station-level pressure at any of the ten stations (QNH altimeter only), so
   FULL_TPR cannot be claimed and the pressure channel is documented as QNH.
3. Spatial context is unavailable for Mumbai and Hyderabad: the audited neighbour
   graph selects no neighbour within 600 km for them, so the replay spatial layer
   honestly reports `UNAVAILABLE` instead of comparing against stations
   657–2070 km away.
4. Root-cause classification, Isolation Forest and LSTM remain Delhi-only;
   replay for the ten Indian stations runs the statistical detector only.
